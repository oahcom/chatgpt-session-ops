# Deployed-source integration tests

These tests exercise deployed-source patch artifacts without requiring production credentials or touching live databases.

**Release compatibility:** `sender-account-identity-pin.patch` applies only to the checked-in 2026-11-28 source snapshot (`chatgpt_send.py` SHA256 `de20a07cfe7667efc4ee79fe3231e6753a1dd09fa4cdbd55279fbcf239dcb3bd`). It is not a production patch. The separately reported production baseline differs and already contains the explicit-account identity preflight while retaining the 429 recursive cross-account rotation. Production-only patch status is **BLOCKED**; see [`sender-account-identity-pin-production.md`](sender-account-identity-pin-production.md). Do not apply the snapshot patch to `/opt/so-sender`.

- `test_sender_account_identity_pin.py`: applies the explicit-account identity patch and shared account-directory contract patch to a temporary copy of the 2026-11-28 Sender snapshot. CI runs this and `test_sender_child_env_account_roots.py` as a dedicated unit-job step (separate from the canonical `tests/` discovery count). It verifies Gateway discovery, CLI identity discovery, and `ChatGPTAPI` credential loading resolve acct1/default and acct2+ to the same physical directories; covers a real empty `accounts/acct1` legacy marker alongside independent acct1 credentials at the auth root, a legacy `BASE/accounts/acct1` directory, CLI `BASE/accounts` fallback, and rejection of symlink account directories and symlink credential marker files; tests `_main_unlocked` allowlist preflight for ordinary explicit `--account --new` (acct5 rejected before API construction/request), explicit 401/403/429 pinning (401/403 do not mutate rotation state; 429 increments the same per-account failure counter as `_attempt_create`, persists the 180-second local rotation cooldown, never recurses or rotates, and the subsequent real auto-rotation planner skips acct1 and attempts acct2), retained automatic rotation, Adapter `NEW_CONV` account-mismatch rejection, legacy `SEND ... -> 401` text classification as `UNAUTHENTICATED` with upstream status 401 (the Gateway health-unavailable signal), legacy `SEND ... -> 429` text classification as `RESOURCE_EXHAUSTED` with upstream status 429 (the Gateway cooldown signal), and the rotation-state `0640` owner-write/group-read mode. Adapter create parsing remains the existing `--account <acct> --new` plus `NEW_CONV` contract; no `--account-only` Adapter route or post-POST header assertion is tested or proposed. Synthetic cookies/tokens only. Run with `python3 -m unittest -v patches.tests.test_sender_account_identity_pin`.
- `test_sender_child_env_account_roots.py`: applies the child-environment and shared account-directory patches to an isolated Sender snapshot and proves both configured path roots reach the CLI child; real `account_router.discover_accounts()` finds acct1 and acct10 with a real empty `accounts/acct1` legacy marker plus independent acct1 credentials at `CHATGPT_AUTH_DIR`; it rejects symlink account directories and symlink credential marker files; a separate CLI child process discovers both identities and loads acct1/default credentials from `CHATGPT_AUTH_DIR` and acct10 credentials from `CHATGPT_AUTH_DIR/accounts/acct10`; and unset roots are omitted. The empty acct1 marker and auth-root credential pair are isolated synthetic fixtures, not evidence that production uses this exact layout. Uses synthetic fixture files/tokens only. Run with `python3 -m unittest -v patches.tests.test_sender_child_env_account_roots`.

- `test_sender_event_outbox.py`: run with the isolated Sender Gateway source snapshot on `PYTHONPATH`.
- `test_sender_mcp_event_pipeline.py`: runs a local mTLS Sender Gateway, MCP collector, SQLite outbox, and mocked HTTPS callback.
- `test_deployed_mcp_events_asgi.py`: run with the isolated deployed MCP snapshot after applying `mcp-server-events.patch` and `mcp-runtime-events.patch`; the callback receiver and Sender Gateway are test doubles.

They are kept under `patches/tests/` because `sender_gateway/` and the deployed launcher are installed from a separate runtime tree and are not part of the canonical Git checkout. No production account files, tokens, private keys, or databases are included.
